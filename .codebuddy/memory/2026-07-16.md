## 修复：npm run build 失败（同日）
- 现象：`npm run build` 报 `error TS2688: Cannot find type definition file for 'babel__template'` 和 `'prop-types'`。
- 根因：`node_modules` 被百度同步盘同步后损坏，`node_modules/@types/prop-types` 与 `@types/babel__template` 目录里只有 LICENSE/package.json/README，**缺 index.d.ts**，TS 自动收录 @types/* 时找不到入口。
- 修复：删除这两个损坏目录后 `npm install --no-save @types/prop-types@15.7.15 @types/babel__template@7.4.4` 重装，`tsc --noEmit` 与 `npm run build` 均 EXIT=0。
- 经验：本项目在百度同步盘目录下，node_modules 易损坏。若再报 TS2688/找不到类型，先查对应 @types 目录是否缺 .d.ts，定向重装即可（不必全量重装）。`npm run dev` 走 Vite/esbuild 不类型检查，损坏时仍可能启动。

## 改进：AI 解读答非所问（同日）
- 用户反馈解读与问题无关。排查：问题有正确传入（SpreadSelector→onStart→useTarotReading→interpretReading），无断线 bug。
- 根因：① AI 调用失败静默回退到 `buildLocalInterpretation`，而本地解读正文是固定通用牌义、不结合问题；② 默认 SiliconFlow Key（写死）可能已失效/GLM-Z1-9B 偏弱，导致几乎总走本地。
- 改动 `src/lib/ai.ts`：
  - system/user prompt 强化：把问题放在【用户的问题】置顶并重复强调，要求"每段都必须回应用户的具体问题""综合建议直接回答问题"，未给问题则做通用指引。
  - 本地回退 closing 明确标注"以上为通用牌义，未结合你的问题展开，请接入 AI 后重新抽取"。
- 注意：prompt 强化仅在 AI 调用成功时生效；若默认 Key 已死仍会回退本地。根本解决需用户在 ⚙ 设置填有效 Key + 更强模型（如 deepseek-chat）。
